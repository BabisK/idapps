updated: 2026-11-10T20:16

- (direction) Enable existing Docker-backed commands from PowerShell using the same bare names, e.g. psql.
- (capability) CAP-1: After setup, invoke existing tools by bare name in PowerShell; psql starts its Docker-backed equivalent with supplied arguments.
- (capability) CAP-2: Preserve service lifecycle operations, persistent data behavior, and CLI interactions where supported on the target platform.
- (capability) CAP-3: Document installation, prerequisites, limitations, and command conflicts so users can resolve the intended command.
- (constraint) Retain existing POSIX behavior and local-development-only scope; preserve forwarding, exit status, working-directory access and interactive use where applicable.
- (assumption) Initial scope assumes Windows PowerShell with Docker Desktop and all existing wrappers; user confirmation pending.
- (question) Which PowerShell editions and operating systems are supported, and are all commands and services in scope?
- (question) What setup and command precedence should apply if a native executable, alias or function already uses a wrapper name?
- (note) Docker Desktop host networking is opt-in and limited; validate localhost connectivity, mounts, user identity, terminal and credential behavior on Windows.
- (event) Coherence and preservation review passed with platform and precedence questions unresolved; no wrapper content discarded.
- (decision) Support PowerShell version 5 and newer.
- (decision) Existing aliases, functions, or native executables take precedence over IDApps of the same name; users invoke the IDApps script by full path to select it.
- (event) Coherence and preservation review passed; operating system and wrapper scope remain assumed pending confirmation.
- (decision) Support all Windows operating systems actively supported by Microsoft; applicability of Docker and PowerShell prerequisites remains to be established.
- (event) Coherence and preservation review passed; scope of commands and services remains an assumption.
- (decision) All existing commands and services are in scope.
- (decision) When Docker is unavailable, the invoked command reports an appropriate error.
- (event) Coherence and preservation review passed; Docker support constraints on Windows editions remain open.
- (decision) Do not handle Windows environments unable to meet compatible Docker or PowerShell prerequisites; still report Docker unavailability clearly.
- (event) Coherence and preservation review passed; all recorded scope questions resolved.
- (decision) CAP-1: Bare names invoke IDApps when no existing command takes precedence; preserve existing alias, function, and native executable precedence, and test explicit full-path invocation for each conflict type.
- (decision) Validate discovery and invocation of every existing root-level IDApps command in PowerShell, using full script path for conflicts.
- (decision) CAP-2: Invoking a service command without arguments starts the service, matching POSIX behavior.
- (decision) CAP-2: Preserve service logs operation and supported options including -f and -t, with POSIX observable behavior.
- (decision) CAP-2: clean fails with a clear message and preserves persistent volume while service runs; after stop clean can remove volume.
- (decision) A missing Docker CLI or stopped or unreachable daemon produces a nonzero exit and clear message identifying the problem.
- (decision) Preserve argument order, boundaries and values; validate multiple arguments, empty arguments and arguments containing spaces or quotes.
- (decision) CLI wrappers support interactive terminal and redirected or piped input and output where underlying tool supports them; preserve stdout, stderr, and underlying exit status and validate both modes.
- (decision) Validate an IDApps client connecting to its service using documented local settings on supported Windows and Docker; document required Docker Desktop networking configuration.
- (decision) Validate current-directory access and aws, helm, kubectl configuration or credential mounts, including paths with spaces and Unicode, without exposing credentials in test output.
- (decision) Validate Windows PowerShell 5.1 and at least one supported PowerShell 7 release on Windows; record Windows, PowerShell and Docker versions and document supported configurations not tested.
- (decision) Setup preserves resolution of same-name native executables, including via PATH; validate before and after setup and retain full-path IDApps invocation.
- (event) All twelve review findings addressed with user approval; coherence and source preservation rechecked.
